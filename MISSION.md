# Mission: Build a Shared Cross-Platform Design System

## Why
Build and maintain a production design system personally, with one shared design language that can serve React and Flutter applications and expand to native Android and iOS when those consumers exist.

## Success looks like
- Explain the boundary between shared foundations and platform-specific implementations.
- Structure a repository containing tokens, documentation, tooling, and component libraries.
- Publish safe, versioned packages that applications can consume and update.
- Implement and govern changes without allowing the platforms to drift apart.

## Constraints
- The user expects to build the system themselves, so the initial architecture must remain manageable for one maintainer.
- Platform libraries should be added in response to real application needs.

## Out of scope
- Building native Android or iOS component libraries before native applications require them.
